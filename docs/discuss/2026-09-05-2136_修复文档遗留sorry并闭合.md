## Line 315 & 336 阻塞原因

核心问题是 **Lean4/ Mathlib 无法对 `ℂ` 进行具体的算术计算验证**：

```
Complex.instDecidableEq : DecidableEq ℂ   -- marked noncomputable
Real.decidableEq        : DecidableEq ℝ   -- marked noncomputable
```

具体阻塞链：

| 尝试的 tactic | 失败原因 |
|---|---|
| `native_decide` | 需要编译 `DecidableEq ℂ`，但 `ℝ` 基于 Cauchy 序列定义，无法计算 |
| `decide` | 同上，`Complex.instDecidableEq` 是 `noncomputable` |
| `ring` | 仅适用于交换环，矩阵乘法非交换 |
| `simp` + `norm_num` | `Matrix.mul_apply` 展开后产生 `Complex.mulAux`（`SMul ℂ ℝ`），`norm_num` 无法化简此类结构 |

根本原因：`ℂ = {re : ℝ, im : ℝ}`，而 `ℝ` 在 Lean4 中是非计算性的（Cauchy 序列/Dedekind 割），因此任何需要判定 `ℂ` 相等性的 tactic 都会触碰 noncomputability 屏障。

## Pauli 基完备库的两条路径

**路径 A：绕过 Pauli 基，直接用 2×2 矩阵代数**

对无迹 2×2 矩阵，有两个关键恒等式可直接从 Mathlib 现有引理推导：

```lean
-- 1. Cayley-Hamilton 对无迹 2×2：M² = ½tr(M²)·I
lemma sq_eq_half_trace_smul (M : Matrix (Fin 2) (Fin 2) ℂ) (hTr : M.trace = 0) :
    M * M = (M.trace_sq / 2 : ℂ) • 1
-- 其中 trace_sq = tr(M²)

-- 2. 反交换子恒等式：PA + AP = tr(PA)·I（无迹 P, A）
lemma anticomm_eq_trace_smul (P A : Matrix (Fin 2) (Fin 2) ℂ)
    (hTrP : P.trace = 0) (hTrA : A.trace = 0) :
    P * A + A * P = (P * A).trace • 1
```

有了这两个，C2 的证明链变为：

```
‖P‖²=1 ⟹ tr(P²)=1 ⟹ P² = ½I
‖A‖²=1 ⟹ tr(A²)=1 ⟹ A² = ½I
⟨P,A⟩=0 ⟹ tr(PA)=0 ⟹ PA+AP=0 ⟹ AP=-PA
[P,A] = PA-AP = 2PA
‖[P,A]‖² = 4‖PA‖² = 4·tr((PA)†(PA))
        = 4·tr(A†P†PA) = 4·tr(AP²A) = 4·tr(A·½I·A) = 4·½·tr(A²) = 2
```

核心步骤 `AP = -PA` 来自 `PA + AP = tr(PA)·I = 0`，然后 `[P,A] = 2PA`，最终用 `P² = ½I` 化简。
