## 正文 §N 格式

```
## 10.N 104az-NNN（日期，标题）

### 动机

<开放项/前条登记/审计点，引用编号>

### 计算（scripts/xxx.py → .out.txt，pyenv 3.11.8）

<数值结果，关键值用 **加粗**>

### 判定

<编号列表式判定：状态、证据通道、升格/维持理由>

### 诚实边界

<记忆值口径、事后性、未覆盖项、不构成证据的说明>
```

## changelog（§9）格式

单行：`> **104az-NNN（日期，标题）**：<浓缩要点>。登记 §10.N + changelog。`

必须含：关键数值、判据判定、脚本名、登记位置。勘误条目同样追加。

## RESEARCH_STATE.md 头部块格式

`> **104az-NNN（日期，标题）**：<1–2 句核心结论 + 脚本名 + 登记位置>。`

## 核验（登记未完成禁止宣布完成）

- 用 Read/Grep 确认 changelog 行 + 正文 §N + RESEARCH_STATE 三处均含编号。
- 可用 `scripts/registration_check.py` 自动核验。
- 用户质询历史：①"为何 §1 无 104az-190/191"②"只更新 changelog 不更新登记表"——证明三处同步是硬约束。
