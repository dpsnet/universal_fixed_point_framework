## 如何阅读本教程

如果你之前没接触过范畴论，或者没接触过 MUFPF，按下面的方式阅读会更顺畅：

1. **不必先懂 MUFPF**：MUFPF 中的递归系统、谱对象、谱丛等例子是“载体”，不是前提。读的时候重点看“一个具体问题如何引出某个范畴结构”，MUFPF 专有名词可以暂时当作黑盒。

2. **三段式读法**：每章建议按这个顺序读：
   - 先读“这一章解决什么问题”或“问题动机段”；
   - 再读“程序员 / 形式化视角”表格，建立代码直觉；
   - 最后浏览 Lean 4 / Mathlib 对应，不强求立刻跑通。

3. **可跳过与不可跳过**：
   - 可跳过：MUFPF 的物理背景、具体公式、谱记号；
   - 不可跳过：范畴、函子、自然变换、伴随、极限、层这些核心结构的定义和直觉。

4. **搭配标准教材**：本教程帮你回答“**这个概念为什么出现、在代码里长什么样**”；标准教材（如 Awodey、Leinster、Riehl）帮你回答“**严格定义、完整证明、还有哪些结构**”。两者平行阅读效果最好。

5. **代码不是必须**：表格中的 Lean 4 代码是为了“落地”而给的可机检对应。即使不安装 Lean，只看“代码直觉”一列也能建立正确直觉。

## 0.1 为什么需要范畴论

范畴论不是一门独立的数学分支（像微积分或线性代数那样），而是一种**组织数学知识的方式**。它的核心思想是：

> **不要只问"一个东西是什么"，而要问"它与其他东西之间有什么关系"。**

在范畴论中，"关系"不是比喻，而是被严格定义的数学对象。一旦你习惯了这种视角，很多看似无关的数学构造会显示出统一的结构。

## 0.2 三个热身例子

### 例子 1：集合与函数

**对象**：集合 $A, B, C, \dots$

**映射**：函数 $f: A \to B$

**复合**：若 $f: A \to B$，$g: B \to C$，则有 $g \circ f: A \to C$

**恒等**：每个集合 $A$ 有恒等函数 $\mathrm{id}_A: A \to A$，定义为 $\mathrm{id}_A(x) = x$

**你早已熟悉的规律**：
- 结合律：$h \circ (g \circ f) = (h \circ g) \circ f$
- 单位律：$f \circ \mathrm{id}_A = f = \mathrm{id}_B \circ f$

范畴论就是把这三个要素——对象、映射、复合——抽象出来，并要求它们满足结合律与单位律。

### 例子 2：群与同态

**对象**：群 $(G, \cdot_G)$、$(H, \cdot_H)$

**映射**：群同态 $\varphi: G \to H$，满足 $\varphi(a \cdot_G b) = \varphi(a) \cdot_H \varphi(b)$

**关键观察**：同态不是任意函数，而是"保持群乘法结构"的函数。

**复合**：两个群同态的复合仍是群同态。

**恒等**：恒等映射 $\mathrm{id}_G$ 是群同态。

群与群同态也构成一个范畴，记作 $\mathbf{Grp}$。

### 例子 3：向量空间与线性映射

**对象**：域 $k$ 上的向量空间 $V, W$

**映射**：线性映射 $T: V \to W$，保持加法和数乘

**复合**：线性映射的复合仍是线性映射。

**恒等**：恒等映射是线性映射。

这构成范畴 $\mathbf{Vect}_k$。

## 0.3 共同模式：什么是范畴

从上面三个例子抽象出来：

一个**范畴** $\mathcal{C}$ 由：
1. 一些**对象**（object）
2. 对象之间的一些**态射**（morphism，即"保持结构的映射"）
3. 态射之间可以**复合**
4. 每个对象有**恒等态射**

并且满足：
- **结合律**：复合顺序不影响结果
- **单位律**：恒等态射不改变任何态射

### 一张图理解

```
对象 A --f--> 对象 B --g--> 对象 C
        \_________h=g∘f________/
```

范畴论研究的不是对象"内部有什么"，而是对象之间"如何连接"。

## 0.4 MUFPF 中的范畴

MUFPF 框架中最基础的两个范畴是：

### $\mathbf{Rec}$（递归系统范畴）

- **对象**：递归系统 $R = (\mathcal{S}_R, \Phi_R, \mathcal{T}_R, \mathcal{M}_R)$
  - 状态空间、自相似演化映射、时间半群、附加结构
- **态射**：保持递归结构的连续映射

### $\mathbf{Sp}$（谱范畴）

- **对象**：谱对象 $E = (\mathcal{H}, A, \sigma(A))$
  - Hilbert 空间、自伴算子、谱
- **态射**：保持谱结构的算子映射

MUFPF 的核心问题可以表述为：

> **是否存在一个从 $\mathbf{Rec}$ 到 $\mathbf{Sp}$ 的"好"函子？**

即：能否把递归动力学系统地翻译成谱数据？答案是谱化函子 $D$。

## 0.5 程序员的直觉

如果你更熟悉编程语言，下面是范畴论语汇与程序结构之间的快速对照。以下对照是帮助理解的类比，不是严格定义；“接口 / 契约”比喻尤其强调范畴论“只规定结构规则、不规定具体实现”的特征。

| 范畴论语汇 | 程序结构直觉 |
|-----------|--------------|
| 范畴 | 纯接口 / 契约：只规定对象类型、态射、复合、恒等及定律，不约束具体实现 |
| 对象 | 接口所允许的类型（如 `A`, `B`），或该接口的一个实现 |
| 态射 | 接口承认的转换（如 `f : A → B`），必须能按接口规则复合 |
| 复合 | 函数复合（如 `g ∘ f` 或 `f >>> g`），接口要求它满足结合律 |
| 恒等态射 | 每个对象上的 `id` / `identity`，接口要求它作为复合单位 |
| 函子 | 把一套接口映射到另一套接口，并保持对象、态射与复合 |
| 自然变换 | 两个函子之间的多态映射（如 `reverse : List A → List A`） |
| 伴随 | 两种接口之间的“最佳近似翻译”或构造/遗忘对（如 `Free ⊣ Forget`） |
| 极限 / 余极限 | 接口下满足通用性质的构造 / 分解（如 `A × B`, `A + B`） |

> **关键直觉**：范畴论不是新的数据类型，而是一套“纯接口 / 契约”：它只规定对象、态射、复合与定律，不约束具体实现。把每个范畴看成一组接口规范，把函子看成接口之间的兼容映射，就能在 Lean 4 / Mathlib 中把这些直觉变成 `Category`、`Functor`、`NatTrans`、`Adjunction` 等可机检的结构。

## 0.6 关键比喻

| 范畴论语汇 | 比喻 |
|-----------|------|
| 范畴 | 一套纯契约 / 接口规范 |
| 对象 | 满足契约的类型或结构 |
| 态射 | 契约承认的类型之间允许的转换 |
| 函子 | 两套接口规范之间的兼容映射 / 适配器 |
| 自然变换 | 两个兼容映射之间的一致化转换 |
| 伴随 | 两套接口之间“最佳近似”的双向翻译 |

## 0.7 为什么这些概念对 MUFPF 重要

MUFPF 试图回答：

> 不同领域中的"谱"——Kerr 黑洞的 QNM 频率、标准模型的粒子质量、NTK 的收敛模式——是否有统一的数学语言？

范畴论提供了这种语言：
- **函子** $D$ 把递归系统翻译成谱对象
- **自然同构**把数值等式 $\lambda_i = e^{-\mu_i}$ 提升为结构对应
- **伴随对** $D \dashv R$ 编码"从动力学归约到谱数据"与"从谱数据重建动力学"的对偶
- **纤维化**把温度、能标、噪声等参数变化统一为"谱族随参数演化"
- **层**把局域谱数据粘合为整体几何

## 0.10 关键要点

- 范畴论的核心是**对象 + 保持结构的映射（态射）+ 复合 + 恒等**。
- 你已经熟悉很多范畴的例子（集合、群、向量空间），只是没有用这个语言表述。
- MUFPF 的 $\mathbf{Rec}$ 和 $\mathbf{Sp}$ 是这一模式的延续：把递归动力学和谱数据都范畴化。
- 范畴论不研究对象内部，而研究对象之间的关系——这正是 MUFPF 统一不同领域"谱"的切入点。
